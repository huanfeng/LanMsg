# P4 Android Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **开工前必须读 `docs/superpowers/plans/2026-10-28-00-roadmap.md`（全局约束 + 共享契约 C1–C8），以及 P2 计划中 `PlatformHooks` / `ThumbnailProvider` 的定义。**

**Goal:** Android 手机装上 APK 后，能与电脑上的 LanMsg 扫码配对成"我的设备"，像聊天一样互传文字、图片、视频、文件，锁屏时按后台档位收到通知，并能从其他 App 分享文件到 LanMsg。

**Architecture:** Rust 侧新增 `lanmsg-ffi`，用 UniFFI 0.28（proc-macro）把 `lanmsg-core::Service` 包成 `LanMsgCore` 对象导出给 Kotlin；`lanmsg-api` 的类型在 `uniffi` feature 下直接派生 UniFFI 类型，不另写一套 DTO。Android 侧单 Activity + Jetpack Compose + Navigation Compose，ViewModel 只依赖 Kotlin 接口 `CoreApi`（真实实现包 `LanMsgCore`，测试用 `FakeCoreApi`），前台服务 `LanMsgService` 持有 core。平台无关的界面规范写在 `docs/ui-architecture.md`，Android 按它实现，iOS/鸿蒙以后复用。

**Tech Stack:** Rust（uniffi 0.28、cargo-ndk）、Kotlin 2.0、Jetpack Compose（Material 3）、Navigation Compose、Lifecycle ViewModel/StateFlow、WorkManager、DataStore、CameraX + ZXing core、Coil 2、JNA、JUnit4 + Robolectric + Turbine + kotlinx-coroutines-test。

**Spec:** `docs/superpowers/specs/2026-10-28-lanmsg-design.md`（§4.2、§9.4、§9.5、§15.2、§16）；共享契约：`docs/superpowers/plans/2026-10-28-00-roadmap.md`

## Global Constraints

路线图「全局约束」全部适用。本阶段额外约束：

- Android 工程根：`android/`；应用模块 `android/app`；包名与 applicationId 都是 `name.apk.lanmsg`。
- `minSdk = 26`，`compileSdk = 35`，`targetSdk = 35`；JVM target 17。
- 前台服务类型 **`specialUse`**，带 `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` = `局域网设备间实时消息接收`；**禁止**用 `dataSync` 类型做常驻（设计 §15.2）。

## Review Focus

1. **App 被系统杀掉后重启 / 前台服务被重建**：`LanMsgCore` 不能被启动两次（两个实例会抢同一个数据库和端口）。→ Task 11 测试 `core_holder_starts_core_once_for_concurrent_acquires`、`release_to_zero_shuts_down_core`。
2. **事件流落后（Lagged）或 App 从后台回来**：聊天页和会话列表必须重新拉取，不能停在旧状态，也不能出现重复消息。→ Task 6 测试 `lagged_triggers_full_reload_without_duplicates`、`message_added_twice_is_shown_once`。
3. **分享进来的是 `content://` URI，而且文件名里有斜杠、为空或重复**：必须安全落地为 outbox 下的普通文件，不能写到目录外。→ Task 7 测试 `import_sanitizes_display_name`、`import_dedupes_same_name`。
4. **用户拒绝通知 / 相机权限**：App 照常可用；扫码页显示"需要相机权限"和"改用数字比对"的入口，不崩溃。→ Task 10 测试 `pair_join_without_camera_permission_offers_sas`；Task 12 测试 `notifier_skips_when_permission_denied`。
5. **用户正在看某个会话时来了该会话的消息 / 会话被设为免打扰**：不弹通知；其他会话照常弹。→ Task 12 测试 `no_notification_for_visible_conversation`、`no_notification_for_muted_conversation`。

- Produces（Kotlin 侧和后续任务依赖这些名字）：
  - `lanmsg-api`：`[features] uniffi = ["dep:uniffi"]`；`lib.rs` 中 `#[cfg(feature = "uniffi")] uniffi::setup_scaffolding!("lanmsg_api");`；C5 中所有**对外**类型（`Request`、`Response`、`Event`、`ErrorCode` 和全部 DTO）加 `#[cfg_attr(feature = "uniffi", derive(uniffi::Record))]`（结构体）或 `uniffi::Enum`（枚举）。`ApiRequest`、`ApiResponse`、`IpcFrame`、`ApiError` **不**导出（它们只在 IPC 中使用）。
  - `lanmsg-ffi`：
    ```rust
    #[derive(Debug, thiserror::Error, uniffi::Error)]
    pub enum FfiError { #[error("{code:?}: {message}")] Api { code: ErrorCode, message: String } }
    impl From<lanmsg_api::ApiError> for FfiError

    #[uniffi::export(with_foreign)]
    pub trait FfiKeyStore: Send + Sync {
        fn load(&self, name: String) -> Result<Option<Vec<u8>>, FfiError>;
        fn save(&self, name: String, bytes: Vec<u8>) -> Result<(), FfiError>;
        fn delete(&self, name: String) -> Result<(), FfiError>;
    }
    #[derive(uniffi::Record)]
    pub struct ThumbnailResult { pub jpeg: Vec<u8>, pub width: u32, pub height: u32, pub duration_ms: Option<u64> }
    #[uniffi::export(with_foreign)]
    pub trait FfiPlatform: Send + Sync {
        fn is_metered(&self) -> bool;
        fn is_wifi(&self) -> bool;
        fn thumbnail(&self, path: String, mime: String, max_edge: u32) -> Option<ThumbnailResult>;
    }
    #[uniffi::export(with_foreign)]
    pub trait EventListener: Send + Sync {
        fn on_event(&self, event: Event);
        fn on_lagged(&self);           // 广播通道 Lagged 时调用，客户端应全量重拉
    }
    #[derive(uniffi::Object)]
    pub struct LanMsgCore { /* tokio Runtime + Service + 监听任务句柄 */ }
    #[uniffi::export(async_runtime = "tokio")]
    impl LanMsgCore {
        #[uniffi::constructor]
        pub fn new(data_dir: String, keystore: Arc<dyn FfiKeyStore>, platform: Arc<dyn FfiPlatform>) -> Result<Arc<Self>, FfiError>;
        pub async fn request(&self, req: Request) -> Result<Response, FfiError>;
        pub fn set_event_listener(&self, listener: Option<Arc<dyn EventListener>>);
        pub fn shutdown(&self);
    }
    ```
  - `adapters.rs`：`pub struct ForeignKeyStore(pub Arc<dyn FfiKeyStore>)` 实现 core 的 `KeyStore`（`FfiError` → `KeyStoreError::Corrupt(message)`）；`pub fn platform_hooks(p: Arc<dyn FfiPlatform>) -> PlatformHooks`（`network_state = Some(Arc::new(move || NetworkState { is_metered: p.is_metered(), is_wifi_or_wired: p.is_wifi() }))`；`thumbnailer` 由 `ForeignThumbnailer(Arc<dyn FfiPlatform>)` 实现 `ThumbnailProvider::thumbnail(&self, path: &Path, mime: &str) -> Option<Thumbnail>`：调用 `p.thumbnail(path 字符串, mime, THUMB_EDGE_PX)`，把 `ThumbnailResult` 转成 `Thumbnail { jpeg, media: MediaInfo { width, height, duration_ms } }`）。
  - 行为约定：
    - `new`：内部建多线程 tokio Runtime（worker 线程 2 个，线程名 `lanmsg-core`），在其上 `block_on(Service::start(cfg))`；`cfg = ServiceConfig { data_dir, listen_port: SERVICE_PORT, discovery: DiscoveryMode::Multicast, keystore: Arc::new(ForeignKeyStore(..)), static_peers: vec![], platform: platform_hooks(..), localsend_port: LOCALSEND_PORT }`。Kotlin 必须在 IO 线程调用 `new`。
    - `set_event_listener(Some(l))`：取消旧的转发任务，启动新任务循环 `subscribe().recv()`：`Ok(ev)` → `l.on_event(ev)`；`Err(Lagged)` → `l.on_lagged()`；`Err(Closed)` → 结束。`None` → 只取消。
    - `shutdown`：取消转发任务，`block_on(service.shutdown())`，之后 `request` 返回 `FfiError::Api { code: Internal, message: "已关闭" }`。重复调用无副作用。
  - `src/bin/uniffi-bindgen.rs`：`fn main() { uniffi::uniffi_bindgen_main() }`；`Cargo.toml` 中 `uniffi = { version = "0.28", features = ["cli"] }` 只给该 bin 用（用 `required-features = ["bindgen"]` 的 feature 门控，`[features] bindgen = ["uniffi/cli"]`）。
  - `Cargo.toml`：`[lib] crate-type = ["cdylib", "lib"]`，`name = "lanmsg_ffi"`；依赖 `lanmsg-core`、`lanmsg-api`（`features = ["uniffi"]`）、`lanmsg-proto`、`uniffi@0.28`、`tokio@1 --features full`、`thiserror@2`；dev：`tempfile@3`。

**§3 全局规则**
- 事件订阅：每个页面在可见期间订阅事件；收到"事件落后"（Android：`CoreApi.lagged`）或 App 回到前台时，当前页面执行一次"全量刷新"（重新发该页的加载请求）。
- 合并规则：列表按 id 去重，后到的同 id 数据覆盖旧数据。
- 错误：请求失败用底部提示条显示 `错误：<message>`；`PeerOffline` 显示文案 `err_peer_offline`；`NotInitialized` 跳回引导。
- 时间格式：今天 `HH:mm`；昨天 `昨天 HH:mm`；今年 `M月d日`；更早 `yyyy/M/d`。
- 大小格式：`< 1024` → `N B`；`< 1024²` → `x.x KB`；`< 1024³` → `x.x MB`；否则 `x.x GB`（一位小数，去掉 `.0`）。
- 时长格式：`m:ss`，超过 1 小时 `h:mm:ss`。
- 头像：圆形，背景色取 `user_id` 前 6 位 hex 映射到 8 色调色板（`#5B8FF9 #5AD8A6 #F6BD16 #E8684A #6DC8EC #9270CA #FF9D4D #269A99`，取 `hex前2位的值 % 8`），中间显示显示名第一个字符；"我的设备"会话用设备图标代替。

**§7 通知规范**
- 渠道：`messages`（高）、`requests`（高）、`transfers`（低，进度）、`service`（最低，前台服务常驻）。
- 消息通知：每个会话一条（通知 id = conv id 的 hashCode），标题 = 会话标题，正文 = 文字或 `notif_new_files`（文件名），同会话新消息更新同一条；点击 → `chat/{conv}`。
- 不弹通知的情况：消息是自己发的；本人状态为「忙碌」（Busy，仍计未读）；会话免打扰；用户正在看该会话；通知总开关关闭；系统未授予通知权限。
- 请求通知：标题 `LanMsg`，正文 `notif_new_request`（名字 + 请求类型文案），点击 → `requests`。

**§8 平台映射说明**：Android = Compose + Navigation + ViewModel/StateFlow（本计划）；iOS = SwiftUI + NavigationStack + ObservableObject（后续）；鸿蒙 = ArkUI + Navigation（后续）。三端共享 §2 路由名、§4 状态字段名、§6 文案键。

      suspend fun acquire(owner: String): CoreApi        // 引用计数 +1；首次在 io 上调用 factory 创建；并发调用只创建一次

## 契约对齐（交由主会话统一处理，本计划不改路线图）

1. **C5 `Response` 形状**：已统一为具名单字段 `{ value: T }`（路线图 C5），UniFFI 生成 Kotlin 为 `Response.X(value = …)`。
2. **`PlatformHooks`**：已与 P2 Task 4 对齐（`lanmsg_core::platform`）：`PlatformHooks { network_state: Option<Arc<dyn Fn() -> NetworkState + Send + Sync>>, thumbnailer: Option<Arc<dyn ThumbnailProvider>> }`；`ThumbnailProvider::thumbnail(&self, path: &Path, mime: &str) -> Option<Thumbnail>`；`Thumbnail { jpeg: Vec<u8>, media: MediaInfo }`。FFI 侧的 `FfiPlatform`（`is_metered`/`is_wifi`/`thumbnail(.., max_edge)`）与 `ThumbnailResult` 保持不变，由 `adapters.rs` 转换。
3. **`FfiError`、`EventListener.on_lagged`** 只存在于 `lanmsg-ffi`，不改 C5（`ApiError` 是结构体，不能直接作为 UniFFI 错误类型；Lagged 通过独立回调传递，不新增 `Event` 变体）。
4. **扫码方案**：CameraX + ZXing core（`com.google.zxing:core`），不用 ML Kit——ML Kit 依赖 Google Play 服务，对国内 APK 分发不友好；ZXing 体积小、离线。
5. **Android 本机设置**（免打扰会话、收到的媒体保存到相册、信任的 Wi-Fi、通知总开关）存放在 Android DataStore，不进 `SettingsDto`，也不在设备间同步。
6. **依赖 P2 的行为**：(a) 未初始化（`Init{JoinExisting}` 之后、配对完成之前）的设备调用 `ListPeers` 能看到可配对的已有设备（Hello 中 `cert = None` 的对端被允许发现与连接，用于 `PairJoin{Device}`）；(b) `Init{FirstDevice}` 时自动创建"我的设备"会话（Task 1 第 4 个测试依赖）；(c) `PairStart` 在手机上也可作为主持方。
7. **下载目录**：Android 在每次 core 启动后用 `SetSettings` 把 `download_dir` 设为 `getExternalFilesDir(DIRECTORY_DOWNLOADS)/LanMsg`（应用专属目录，无需存储权限），core 照常在该目录写文件；图片/视频再按本机设置复制进 MediaStore。
