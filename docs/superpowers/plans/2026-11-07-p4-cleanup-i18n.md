# P4 后清理：英文日志与错误、界面本地化、结构化文本 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** core 及所有 Rust crate 不再产出给人看的中文；日志与错误消息一律英文，界面只按结构化数据（ErrorCode、枚举、字段）从各端本地化资源取文案；同批补上"已被所有目标下载"接口和配对二维码瘦身。

**Architecture:** 契约集中在 `crates/lanmsg-api/src/types.rs`：错误加 `ErrorCode::Unimplemented`，配对失败、系统消息、文件来源、会话标题、请求预览改为结构化字段；core 只填数据，桌面（`crates/lanmsg-desktop/src/strings.rs`）、Android（`res/values/strings.xml`）、lanmsgd（新建 `crates/lanmsgd/src/strings.rs`）各自拼文案。最后用一个检查脚本把"非测试、非注释的 Rust 字符串字面量不含中文（白名单文件除外）"固定下来。

**Tech Stack:** Rust（serde、uniffi 0.28 proc-macro）、Kotlin/Compose、windui。

**Spec:** 用户决定（见下方 Global Constraints，原话来自会话与 `memory/feedback-english-log-messages.md`）；遗留事项清单见 `docs/superpowers/reports/2026-11-07-p4-stage-report.md` §5、§7；现状摸底结论写在各任务的"现状"行里。

## Global Constraints

- 日志（tracing / Log.*）与异常/错误消息字符串一律英文；注释仍用中文；界面文案只放本地化资源（桌面 `strings.rs`、Android `strings.xml`、lanmsgd `strings.rs`）。
- 界面不得把 `ApiError.message` 或任何 core 给出的自由文本当作文案显示给用户（用户自己输入的内容除外：消息正文、显示名、设备名、文件名）。
- `docs/ui-architecture.md` §6 文案表与 `strings.xml` 一一对应，用 `scratchpad/cmp_strings.py` 比对零差异。
- uniffi：api 层文档注释里不得出现 `/*`（会被抄进 Kotlin KDoc 形成嵌套注释）。
- 线上协议仍未发布，不需要兼容旧版本，但收到未知取值必须降级为"未知"分支而不是崩溃或显示原文。
- 遵守 `scratchpad/p4-rules.md`（环境、设备、Git 纪律）；提交尾行 `Plan: P4/Cleanup-i18n`。
- CLI（`lanmsg-cli`）是开发与测试工具，用户输出改为英文；`scripts/e2e-acceptance.sh` 同步改匹配串。

## 设计决定（主控已定，实施者照做）

1. `ApiError { code, message }` 结构不变；`message` 改英文、仅供日志与排障。新增 `ErrorCode::Unimplemented`，替代 Android 对 `"未实现："` 前缀的匹配。
2. 配对失败：新增 `PairFailReason` 枚举（`Timeout`、`Cancelled`、`NotOpen`、`WrongSecret`、`Busy`、`CertMismatch`、`BadSignature`、`IdentityMismatch`、`InvalidName`、`Unknown`）。线上 `PairMsg::Abort { reason: String }` 字段不改名，取值改为稳定的 snake_case 键（`timeout`、`cancelled`、`not_open`、`wrong_secret`、`busy`、`cert_mismatch`、`bad_signature`、`identity_mismatch`、`invalid_name`），未知键解析为 `Unknown`。`PairStateDto::Failed { reason: PairFailReason }`。
3. 系统消息：`MessageBodyView::System { text }` 改为 `MessageBodyView::System { event: SystemEventView }`，`SystemEventView` 变体：`DeviceAdded{name}`、`DeviceRemoved{name}`、`ContactAdded{name}`、`ContactUpdated{name}`、`NicknameUpdated{name}`、`MessagesDeleted{count: u32}`、`Recalled{author_name, by_me: bool}`。
4. 会话标题：`ConversationSummary.title` 对 `ConvKind::SelfDevices` 返回空串，各端按 kind 显示本地化的"我的设备"。
5. 文件来源：`FileItemView.source_label` 删除，换成 `source_name: String`（作者显示名）、`source_is_me: bool`、`holder_name: Option<String>`（未下载时持有该文件的设备名）。"已下载"由 `state == BlobState::Local` 推出。
6. 请求预览：`RequestView.preview` 对 `RequestKind::Contact` 为空串，各端按 kind 显示文案；消息/文件请求的 preview 是用户内容，保持原样。
7. "已被所有目标下载"：下载完成方把 `BlobHave` 也发给该消息作者的设备（现在只发给自己用户的设备）。新增 `Request::DeliveredLocalPaths { under: String }` → `Response::Paths(Vec<String>)`：返回本机 `blob_local` 中路径以 `under` 开头、且"所在消息会话的每个其他成员设备（未吊销）都已在 `blob_holders`"的本地路径。Android 清理副本 = 7 天前的 ∪ 已全部送达的。
8. 配对二维码：`pairing.rs::local_addrs()` 过滤 IPv6 链路本地（fe80::/10）与 IPv4 链路本地（169.254/16）；过滤后为空时退回原列表，保证仍能配对。

## Review Focus

1. 收到未知 Abort 键或未知 ErrorCode（对端新版本）——界面显示通用失败文案，不崩溃、不显示原始字符串。→ Task 3、Task 2 测试。
2. 某个界面路径漏改，仍把英文 `message` 原样弹给用户 —— 两端都要有"任意 ErrorCode 都映射到资源文案"的穷尽测试。→ Task 2。
3. 系统事件里的名字为空（设备被删、用户未知）—— 文案仍通顺（用设备短 ID 或"对方"兜底，由 core 填名字时保证非空）。→ Task 4。
4. "已全部送达"判定：会话成员有设备离线、已吊销、或成员只有自己（我的设备会话）时结果正确，且绝不把对端尚未下载的文件判为可删。→ Task 7。
5. 只有链路本地地址的机器（无 DHCP）仍能生成可用的配对二维码。→ Task 8。
