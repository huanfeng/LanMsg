# P2 同步与文件 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **开工前必须读 `docs/superpowers/plans/2026-10-28-00-roadmap.md`（全局约束 + 共享契约 C1–C8），并了解 P1 计划 `2026-10-28-01-p1-core-skeleton.md` 中各任务 Interfaces 定义的名字——本计划直接引用它们。**

**Goal:** 在 P1 骨架上实现"我的设备"配对与吊销、联系人双向确认与陌生人请求、多设备消息同步（含离线补齐与转交）、已读/撤回/删除，以及跑满局域网带宽的文件（Blob）传输与自动下载策略。

**Architecture:** 新增 core 模块 `trust`（联系人、请求、吊销、准入）、`pairing`、`sync`、`blob/*`（哈希、数据连接协议、服务端、传输引擎、策略）、`settings`、`platform`；`Messaging` 的入站处理拆成"准入判定 → 入库 → 入库后分派"。所有状态变化在自己的设备之间通过"我的设备"会话里的**隐藏系统消息**同步，复用同一套消息同步机制。Blob 内容走独立的数据连接（同端口，TLS 后首字节区分通道）。

**Tech Stack:** P1 全部 + `hmac`/`sha2`（配对 MAC）。不新增其他依赖。

**Spec:** `docs/superpowers/specs/2026-10-28-lanmsg-design.md`（§5、§8、§9、§17）；共享契约：`docs/superpowers/plans/2026-10-28-00-roadmap.md`

## Global Constraints

路线图「全局约束」全部适用。本阶段额外约束：

- 本阶段用到的常量（路线图 C1「P2 Task 1 追加」段）**已由 P1 Task 2 一次定义**，本阶段直接使用，不得重复定义。
- P1 已提供：`Hello.listen_port`、`PeerInfo.dial_addr`（= 对端 IP + 对端监听端口，任何"重新拨号"都用它，不得用 `PeerInfo.addr`）；`Init{FirstDevice}` 已创建 SelfDevices 会话、写 `users(is_self)` 与 setting `"display_name"`/`"device_name"`；C5 全部 API 类型与 `ServiceConfig.localsend_port`。
- 共享状态的锁一律用 `std::sync::{Mutex, RwLock}`，不得跨 `.await` 持有（需要在锁内取值后先释放再 await）。
- 新增帧变体使用 C4 预留的类型号；数据连接帧是**独立的类型号空间**（Task 1 `DataFrame`），与 `Frame` 不共用编号。
- 本阶段的迁移是 `MIGRATIONS[1]`（schema v2），只追加这一个元素，不得修改 `MIGRATIONS[0]`。P3 将追加 `MIGRATIONS[2]`、P5 追加 `MIGRATIONS[3]`。
- 所有入站数据（帧、数据连接请求、配对消息）必须先校验身份与权限再处理；校验失败只断开该连接或丢弃该条，不得 panic。
- 缩略图生成不在本阶段：`BlobMeta.thumb` 恒为 `None`，除非 `PlatformHooks.thumbnailer` 被注入（P3 注入）。
- core 集成测试统一使用 `crates/lanmsg-core/tests/common/mod.rs`（Task 4 建立）的辅助函数。

## Review Focus

1. **配对时口令错误或中间人**（二维码口令被篡改、TLS 导出值不一致）：配对失败，加入方保持未初始化，不获得用户私钥。→ Task 7 测试 `qr_pairing_with_wrong_secret_fails_and_leaks_nothing`。
2. **转交消息早于联系人/证书到达**（手机先从电脑收到同事的消息，但还不认识同事的设备）：消息不得被当成陌生人请求，也不得丢失。→ Task 9 测试 `relayed_contact_message_is_accepted_on_new_device`。
3. **下载中途源设备断开或进程被杀**：重启后从已校验分段继续，最终文件哈希正确；`.part` 不会被当作完成文件。→ Task 12 测试 `transfer_resumes_after_restart_with_verified_segments`。
4. **发送方在发送后修改或删除了原文件**：对方下载时得到 `NotFound`/失败，而不是收到与哈希不符的内容。→ Task 11 测试 `serving_modified_source_returns_not_found`。
5. **无权限设备请求 Blob**（陌生人猜测哈希来拉文件）：数据连接拒绝。→ Task 11 测试 `stranger_cannot_fetch_unshared_blob`。

    2. 设备已吊销（`store.is_revoked`）→ 拒绝。

### Task 6: 陌生人消息门控（接收一次 / 加为联系人 / 拒绝 / 屏蔽）

**Files:**
- Modify: `crates/lanmsg-core/src/{trust.rs,msg.rs}`、`crates/lanmsg-core/src/service/handlers.rs`、`crates/lanmsg-core/tests/trust.rs`

**Interfaces:**

  - ```rust

    impl Trust {
        pub fn gate_inbound(&self, from: &PeerInfo, env: &Envelope, now: i64) -> Result<GateDecision, CoreError>;
        pub async fn respond_message_request(&self, msg: &Messaging, req: &RequestRow, action: RequestAction, now: i64) -> Result<(), CoreError>;
    }
    ```
  - `gate_inbound` 判定顺序（`author_user` = 作者设备所属用户）：
    1. `from` 设备属于自己 → `Accept`（自己设备转交的一律信任；门控只在首个接收设备上发生）。
    2. `author_user == self` → `Accept`。
    3. 作者用户 `Blocked` → `Drop`。
    4. 作者用户 `Accepted` 联系人 → `Accept`。
    5. 会话 gate 为 `Open` 且 `gate_until` 为空或 `> now` → `Accept`（`gate_until` 为空表示联系人会话或自己的会话）。
    6. `from.path` 不是 `Lan` 且不是（`Vpn` 且 `from.outbound`）→ `Drop`。
    7. 其余 → 会话 gate 置 `Pending`，`upsert_open_request(kind = 消息体为 Files/Folder ? File : Message, conv = env.conv, preview)` → `Pending { request_id }`。preview：Text 取前 50 个字符；Files 为 `"{首个文件名} 等 {n} 个文件（{总大小人类可读}）"`（n=1 时省略"等 n 个文件"）；Folder 为 `"文件夹 {name}（{n} 个文件）"`。
  - `Messaging::on_frame` 的 `SyncPush` 处理改为：验签 → 作者设备已知 → 会话存在性/成员校验（Task 9 定义，本任务先沿用 P1 的 DM 规则）→ `gate_inbound`：`Accept` → `insert_envelope`；`Pending` → `insert_envelope_hidden(.., hidden = true)`，**仅当本次新插入且这是该请求的首条**时发 `IncomingRequest`（后续合并到同一请求的只更新 preview，不再弹事件）；`Drop` → 不入库。`Accept`/`Pending` 回 `Ack`；`Drop` 不回 `Ack`（被屏蔽者本来就会被断开且无法重连，见 Task 5，其消息在发送方保持 `Sending`）。

    - `AddContact`：执行 `AcceptOnce` 的效果（gate_until 置 `None`），再走 Task 5 的 `request_contact`（对方会收到联系人请求）。
    - `Reject`：`mark_deleted` 该会话中该用户的消息；gate 置 `Rejected`；关闭请求。之后该用户的新消息再次进入规则 7（重新生成请求）。
    - `Block`：同 Reject，并把联系人状态置 `Blocked`（Task 5 的 Block 效果）。
  - 陌生人会话中的文件**从不**自动下载（Task 13 策略读 gate/联系人状态实现）。
