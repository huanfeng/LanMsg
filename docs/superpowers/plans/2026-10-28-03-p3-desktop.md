# P3 桌面客户端 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **开工前必须读 `docs/superpowers/plans/2026-10-28-00-roadmap.md`（全局约束 + 共享契约 C1–C8）。** 涉及 windui 仓库的任务（Task 1–5）另须先读 `/home/dufeng/develop/windinput/wind-ui-rust/AGENTS.md`。

**Goal:** 在 Windows / Linux 上完成核心场景的桌面体验：`lanmsgd` 带托盘、通知、自动拉起界面；`lanmsg` 界面进程（windui）覆盖首次向导、会话、聊天、联系人与请求、我的设备与配对、文件视图、设置；关闭窗口即退出界面进程；macOS 编译通过、离屏截图通过。

**Architecture:** `lanmsgd` = 主线程跑 windui **零窗口常驻模式**（`App::resident(..).tray(..).run_resident()`，只有托盘，没有窗口缓冲）+ 后台线程跑 tokio（`Service` + IPC 服务）；无图形环境时退化为无头模式。`lanmsg` 界面进程 = windui 窗口 + 后台线程里的 `IpcClient` 桥，所有状态逻辑放在纯数据的 `Model` 里（可单测），界面只是把 `Model` 映射成 `Signal` 与 `Element`。图片/视频解码在 `lanmsg-media`（经 windui 的 `register_decoder` 扩展点接入，不改 windui 核心），缩略图由短命进程 `lanmsg-thumb` 生成。windui 只补通用能力（Task 1–5）。

**Tech Stack:** windui（path 依赖）、image 0.25、keyring 3、qrcode 0.14、windows 0.58（仅 Windows：Shell 缩略图、注册表）、zbus 4（仅 windui Linux 托盘/通知）、ffmpeg/ffprobe（运行期可选外部程序）。

**Spec:** `docs/superpowers/specs/2026-10-28-lanmsg-design.md`（§4.1、§4.2、§10、§15.1、§15.3、§16、§17）；共享契约：`docs/superpowers/plans/2026-10-28-00-roadmap.md`；前置：P1、P2 计划已完成。

## Review Focus

1. **`lanmsgd` 运行在没有图形环境的 Linux（SSH、NAS、无 `DISPLAY`/`WAYLAND_DISPLAY`）**：必须自动进入无头模式继续服务，不能因为 windui 连不上显示服务器而退出。→ Task 8 测试 `headless_detection_without_display_env`。
2. **用户在 IME 组字中按 Enter**（中文输入法确认候选）：只上屏候选词，不能把半截消息发出去。→ Task 2 测试 `enter_during_preedit_does_not_submit`。
3. **聊天中向上翻看历史时有新消息进来**：视图不能跳到底部打断阅读；在底部时才自动跟随。加载更早消息后视图停在原来看的那条上。→ Task 1 测试 `does_not_follow_when_scrolled_up`、`prepend_keeps_first_visible_row_anchored`。
4. **损坏 / 超大 / 伪造扩展名的图片文件**（例如 2 万×2 万像素的 PNG、改名为 .jpg 的 zip）：缩略图生成失败时返回 `None`，不 panic、不占满内存；`lanmsg-thumb` 进程有超时被杀。→ Task 6 测试 `rejects_oversized_dimensions`、`garbage_bytes_return_none`；Task 8 测试 `thumbnailer_kills_hung_child`。
5. **`lanmsgd` 不在运行时打开界面 / 界面运行中 `lanmsgd` 被杀**：界面应尝试拉起 `lanmsgd` 并重连，断开期间顶部显示"未连接后台服务，正在重试…"，恢复后自动刷新，不崩溃。→ Task 10 测试 `disconnect_then_reconnect_triggers_full_refresh`。

### Task 1: windui — 滚动容器跟随底部与边缘回调

**Files（windui 仓库）:**

- Modify: `docs/API_GUIDE.md`（滚动章节加一节）

**Interfaces:**
- Produces（LanMsg Task 12 使用）：
  - `pub enum ScrollEdge { Top, Bottom }`（`windui::prelude` 导出）
  - `Element::stick_to_bottom(self, on: bool) -> Self`：仅对滚动容器（`Element::scroll()` 及 `list_signal` 返回的元素）生效。语义：首次布局时滚到底；之后每次 arrange，若上一帧视口底边距内容底边 ≤ 4 逻辑像素（"在底部"），内容变高后仍保持在底部；否则保持 `scroll_y` 不变。
  - `Element::preserve_on_prepend(self, on: bool) -> Self`：仅对 `list_signal`/`keyed` 生成的滚动列表生效。语义：数据更新后若在原第一个可见行之前插入了新行，`scroll_y` 增加插入行的总高度，使原第一个可见行在视口中的位置不变。
  - `Element::on_scroll_edge(self, f: impl FnMut(&mut EventCtx, ScrollEdge) + 'static) -> Self`：滚动位置到达顶部（`scroll_y == 0`）或底部（距底 ≤ 4px）时触发一次；离开该边缘超过 16px 后重新武装。内容不足一屏时不触发。

      1. `Connected` → `Call(GetSelf)`、`Call(ListConversations)`、`Call(ListRequests)`、`Call(GetSettings)`；`Resync` 同上并在有 `current_conv` 时重新 `ListMessages`。
      2. `SelfInfo` 回复 `initialized == false` → `page = Wizard`；否则若 `page == Wizard` 则改 `Chats`。

      4. `Messages{older:false}` 回复 → 替换 `messages`；`older:true` → 前插；`has_older = 返回条数 == MESSAGE_PAGE`；总数超过 `MESSAGE_WINDOW_MAX` 时从**末尾**丢弃（前插时）并置 `has_newer = true`（窗口与最新消息之间出现缺口）；`has_newer` 为真时 `MessageAdded` 不追加到窗口（仍由 `ConversationUpdated` 更新会话摘要），用户滚到底部时（`on_scroll_edge(Bottom)`）发 `ListMessages{before: None, limit: MESSAGE_PAGE}` 重新拉取最新一页（`Messages{older:false}` 替换窗口）并清 `has_newer`；`open_conv` 与 `Messages{older:false}` 回复复位 `has_newer`。
      5. `Event::MessageAdded`：属于 `current_conv` 且 id 不存在 → 追加；超过窗口上限从**头部**丢弃并置 `has_older = true`；窗口有焦点时额外 `Call(MarkRead)`。
      6. `Event::MessageUpdated` → 按 id 原地替换（不存在则忽略）。
      7. `Event::ConversationUpdated` → 按 conv 替换或插入，`convs` 按 `last_hlc_millis` 降序。
      8. `TransferProgress` → 写入 `transfers`；`TransferFinished` → 删除，`ok == false` 时 `toast = Some("下载失败：{error}")`。

      11. `set_window_focused(false)` → `Call(SetUiFocus{None})`；`true` 且有 `current_conv` → `Call(SetUiFocus{Some(c)})`。

      13. `Reply` 为 `Err(e)` → `toast = Some(e.message)`。
      14. `search(q)`：`search_query = q`；`q.trim()` 为空 → 清空 `search_results`、无 Effect；否则 `Call(SearchMessages{query: q.trim(), conv: None, limit: 50}, ReplyTag::Search{query: q.trim()})`。`Search{query}` 回复只在 `query == search_query.trim()` 时写入 `search_results`（丢弃过期回复）。
